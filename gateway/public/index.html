Pay an AI agent only after Concordium vouches for it.

When agents pay each other over x402, the buyer cannot tell who it is paying, the seller cannot tell who is buying, and nobody can prove what was sold was not changed later. VeriFlow closes all three on Concordium. Try both below: no wallet, nothing to install.

Buyer → seller

Check before signing

Agent Registry badge, Active, card hash, and payTo = the agent's own on-chain wallet. A guard any x402 agent can wrap around its client.

Seller → buyer

Prove, reveal nothing

A Verify & Access zero-knowledge proof (18+, allowed country), re-checked at every payment; the payer must be its agent's wallet.

The record

Cannot be rewritten

Every call is committed on-chain before its outcome, one per asset and day, under a scoring rule registered first.

Try 1Watch an agent buy one call

Our buyer agent #1478 runs on this server. It checks this seller, agent #1313, on Concordium before signing anything, pays 1 testnet CCD over x402, and the seller checks it back. You pay nothing. Then your browser checks the call it bought against the chain.

Try 2Pay through the escrow contract

The same buyer pays agent #1313 1 testnet CCD through our escrow contract . The contract calls the CIS-8004 Agent Registry itself: when the CCD comes in (held only for an Active agent with an agentWallet, which it records), and again at release (paid only to that recorded wallet, only if the registry still names it). First it is asked about three agents it must refuse; those are read-only calls, nothing is sent. You pay and sign nothing.

Try 3Check another team's seller before paying

The same checks our buyer runs, as a guard any x402 agent can wrap around its own client (npm install concordium-x402-guard). This server calls the seller, reads whom it wants to be paid, and checks that seller on Concordium. Nothing is paid. Results are cached for a minute.

On-chain commitments

Since 2026-11-22 every call is committed to contract v2 <13115,0>: at most one per asset and day, accepted only in the day after that close, before any sale and long before the 7-day outcome it is scored on. Rows marked v1 come from the retired system (<13094,0>), which allowed more than one commit per day; that is why v2 replaced it. No hit rate is shown: the score is computed only from the chain and Binance by the scoring rule registered on-chain before the first v2 call. This page recomputes hashes in your browser but reads transactions through this server; for a check that does not, open the transaction on CCDExplorer.
